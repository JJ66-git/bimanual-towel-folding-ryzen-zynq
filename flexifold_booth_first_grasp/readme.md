首次载入互动自动经当前 Jupyter 登录同步十个带 SHA-256 校验和备份的 B35 文件（协议、显示驱动、状态模型及中文字体）。使用已选 B35 位流，等待服务真正就绪后，在真实 PL 上验证 2.650→STOP、2.540→PASS、2.550→STOP、2.540→PASS，并核对板端 LCD 状态的 SESSION/SEQ/角度及图片哈希。启动或显示核对失败时不启用实板互动控件、不回退为软件通过；保存板端控制台诊断并尝试恢复任务显示服务。记录在 `verification/<本轮时间>/b35_check.json`，实体屏幕显示仍需目视确认。以后文件一致时复用部署，只在任务/互动来源模式切换时重启受管理服务。

同窗互动的四个主要按钮放大至 64–68 px 高，并增加“修正到安全值”直达按钮。板屏使用与任务一致的中文字体和配色，明确区分“动作目标超范围”和“本条规则检查通过”；PASS 只说明这条诊断输入未触发规则，不代表折叠任务成功。任务结束默认显示“结果待现场确认”，只有明确的现场确认才显示操作员判断。

工作人员预先接好独立右主臂 USB-CAN，并启用 1 Mbps CAN。按提示插好主臂电源，点击「插好了，检查并开始」。面板按接口名和 USB 序列号排除左右执行臂，识别唯一的独立适配器。收到完整的主臂信号后自动开始采集。评委手动操作主臂和夹爪，再点击「结束并保存」。指定已确认接口仍可用 `AIPC_LEADER_CAN`。真实记录保存在 `collected_data/episodes/`。独立展台网页支持可选相机上传；同窗采集未接图像时保留缺项标记，`training_ready=false`。

## 立即打开

在本目录执行，系统 Python 3.10+ 即可，无需安装第三方包：

```bash
./start_booth.sh
```

浏览器自动打开 http://127.0.0.1:8765/ 。也可用 `python3 -B booth.py` 启动。

- 项目演示：`http://127.0.0.1:8765/#demo`
- 调关节互动：`http://127.0.0.1:8765/#guard`
- 采数据互动：`http://127.0.0.1:8765/#capture`

未接 FPGA 时明确显示“软件参考预演”。未接主臂时，真实采集按钮不可用，可点“切换示例排练”，再手动开始、结束，体验动作曲线和保存。示例始终标明合成来源，并保存在独立的 `rehearsals/`。

## 互动 01：您来修好这条动作

进入页面自动载入一条人为注入越界的历史动作：右臂 J2 = 2.650 rad。

评委只需把一个滑块拖回绿色区。姿态示意图和角度立即变化，停下滑块约 350 ms 或松手时自动发起检查；没有额外的发送步骤。大屏显示本次结果，开始与调整后的结果并排显示。点“重新挑战”恢复越界案例。

- 绿色边界：2.540 rad；2.550 rad 开始越界。
- 姿态是 J2 角度示意，不是机器人完整运动学仿真。
- 案例底稿为历史控制第 201 步，只修改目标向量的右臂 J2；原 ACT、反馈与修正保持原值。
- “检查通过”表示当前诊断规则没有触发违规，不表示毛巾折叠成功。
- 连接 FPGA 后只使用匹配的实际回包；超时和参考不一致会明确提示。连续拖动时串行发送并保留最新目标，旧结果不会替代新位置的结果。
- “查看案例与诊断信息”里保留原始画面、SEQ、SESSION、MASK、BUILD_ID，以及“检查真实原样本”。原样本 1.798876 rad 按原值发送，不受滑块步长四舍五入影响。

话术：“老师，这条动作的关节目标越界了。您把圆点拖回绿色区，看看 FPGA 怎么判断。”

## 互动 02：您来采一条 VLA 示范

这是 VLA 全流程中“采集示范数据”这一步的互动入口。**开始和结束都由评委决定，不设置三秒自动停止。**

现场主操作只有两步：

1. 点“开始采集”，自由示范一段合爪、轻抬等动作。已用一个默认任务指令填好输入框，工作人员可事先修改。
2. 点“结束并保存”。后端停止采样，将本条数据保存到专用目录，页面显示真实时长、动作条数、图像数量和保存路径。可回放或下载 JSON 副本。

页面用三块信息解释 V/L/A：

| 内容 | 实际保存的信息 | 作用 |
| --- | --- | --- |
| V 场景图像 | 接入相机后保存本次现场 JPEG、服务器接收时间和浏览器相对时间 | 提供视觉输入，让模型知道眼前场景 |
| L 任务指令 | 本条示范对应的一句任务文字 | 说明希望完成什么 |
| A 示范动作 | 右主臂六关节角、夹爪开度、采样时间；带 CAN 分量年龄 | 作为动作示范，后续整理为学习目标 |
| 时间与对应关系 | 每张图像与附近动作的编号、时间差及是否匹配 | 帮助整理画面与动作的对应关系 |

**数据专用文件夹**默认位于本目录的 `collected_data/`：

```text
collected_data/
  episodes/                     # 真实主臂示范
    ep_20261113_210000_ab12cd34/
      metadata.json             # 来源、任务、时长、条数、完成状态和数据缺项
      instruction.txt           # 任务文字
      samples.jsonl             # 每行一条主臂动作及相对时间
      frames/000000.jpg         # 本次相机画面；未接相机时目录为空
      frames.jsonl              # 图像文件名和时间信息
      alignment.jsonl           # 图像到动作的近邻对应
      README.txt                # 字段含义与用途
  rehearsals/                   # 合成排练，独立保存
```

目录由后端自动创建，和浏览器下载目录无关。每次开始都会新建目录，不覆盖前一条。原始动作按标称 25 Hz 逐条落盘；结束时生成最终元数据和对应关系。主臂断流或正常关闭采集服务会将片段标为 `interrupted` 并保留，成功结束标为 `complete`，保存出错标为 `save_error`，不会报告正常保存成功。

可通过 `--data-dir /绝对路径/采集目录` 自定义专用目录。页面也能查看已保存记录；刷新页面后可重新接管当前正在采集的条目，再点结束。浏览器关闭前应先结束保存；后端采集不会因为切换或刷新页面自动结束。

### 可选相机

工作人员点“接入相机”，允许浏览器使用摄像头。此后预览显示当前相机，采集过程中约每秒保存 5 张 JPEG，与动作放在同一条目录中。相机未接入、权限被拒绝或掉线时，页面明确显示状态；本条仍可保存任务文字与动作。

图像按服务器接收时刻与最近的动作配对，200 ms 内才标为匹配；同时保留浏览器相对时间。这是原始素材的近邻对应，不是相机曝光同步。完整训练数据还需实际从臂反馈、所需相机视角、筛选校准及格式转换。元数据始终保留这些缺项与 `training_ready=false`，不把现场短示范直接当作已完成的训练数据集。

### 衔接整个项目的话术

“老师，您点开始，自己示范一下，做完后再点结束。这里保存了相机看到的画面、希望完成的任务，以及示范动作。时间戳把它们对应起来。像这样的示范经过筛选和整理，才会用于训练或微调。部署时，AI PC 根据画面和任务推理动作，再由 FPGA 检查，并结合执行反馈继续观测。”

页面上方持续显示“采集示范 → 整理与对齐 → 训练/微调 → AI PC 推理 → FPGA 检查 → 执行反馈”的关系，当前采集阶段高亮；“这些数据有什么用”可展开讲解。本次保存不现场更新模型，也不执行主从臂运动。

## 接主臂

沿用现场已配置的 Piper 右主臂模式，使用独立 SocketCAN。保持从臂断电，并与这条主臂 CAN 链路物理断开。程序只接收，不发送 CAN 控制帧，不切换机械臂模式。

```bash
ip -br link show type can
./start_booth.sh --leader-can can0
```

`can0` 替换为主臂实际接口；速率沿用项目 1 Mbps。CAN 配置由现场技术员按实际接线完成。程序等待三组关节和一组夹爪帧都新鲜、完整后才允许采集；超过 200 ms 的分量不当作有效实时数据。

## 接 FPGA：B34 / FPG1 v3

新版默认使用 FPG1 v3，兼容当前 B34 报文、配置 CRC 和 BUILD_ID。板端需要使用下方展台专用显示入口，才能在物理小屏直观看到 STOP/PASS；原 B34 观测服务的小屏主要显示折叠阶段。

### 板端展台入口

1. 将本目录的 `board_addon/` 两个 Python 文件上传到板端，推荐放在 B34 根目录下的 `booth_addon/`。板端当前 B34 根目录为 `/home/xilinx/jupyter_notebooks/fpga_fpg1_v3_b34_20261113`。
2. 按已有板卡管理流程停止当前占用 PL 的观测服务，保留现场其他任务。新服务使用相同独占锁，已有服务运行时会拒绝抢占。
3. 从板端终端启动以下命令。`--peer` 必须是 AI PC 实际有线 IPv4；日志目录必须是新目录。

```bash
python3 /home/xilinx/jupyter_notebooks/fpga_fpg1_v3_b34_20261113/booth_addon/booth_server.py \
  --runtime /home/xilinx/jupyter_notebooks/fpga_fpg1_v3_b34_20261113 \
  --peer 192.168.2.10 \
  --log-dir /home/xilinx/jupyter_notebooks/booth_runs/round_01
```

它复用已部署的 B34 协议、PL 访问、时钟配置与 LCD 驱动，不需重新生成位流。日志和画面均标记历史诊断来源；不会发送 FVE1 视觉成功证据或看门狗提交。退出使用 Ctrl+C，再按原流程恢复观测服务。

小屏使用真实 PL 回包显示：

- `STOP / TARGET RANGE`：目标越界。
- `PASS / NO VIOLATIONS`：没有触发诊断规则。
- J2 目标角、上限、SEQ、SESSION、MASK；结果标为最后一次历史检查。

`preview/lcd_stop.png` 与 `preview/lcd_pass.png` 为该渲染器生成的排版预览，使用合成输入，不代表实体小屏验收。

### PC 入口

```bash
./start_booth.sh --fpga 192.168.2.99
```

两套硬件同时连接：

```bash
./start_booth.sh --fpga 192.168.2.99 --leader-can can0
```

先发送合法 probe，再发送递增的诊断步与序号；历史底稿步数仍在结果里保留。用户每次调整是一个新的诊断 tick，诊断 elapsed 每次加 40 ms，不宣称是真实任务运行时间。空闲五秒后使用新会话重新 probe；不靠后台持续发包维持租约。异常后等待五秒再重试。

交互前验收：2.650 → STOP，2.540 → PASS，2.550 → STOP；大小屏角度和 SEQ 对应。大屏出现“与软件参考不同”或超时应先检查配置和链路。

旧 FPG1 v1 板端必须显式指定 `--protocol v1`，不会自动降级。旧服务启动方法仍为它自己的 `scripts/run_fpga.sh`；不要把旧服务当作 B34 服务。
