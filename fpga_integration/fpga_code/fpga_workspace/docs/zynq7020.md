## AXI4-Lite 寄存器表

32 位数据、16 位 AXI 字节地址；当前实际定义的寄存器仍集中在 4 KiB 内。向量每项有符号 int32，负数用二补码。所有寄存器在同一 s_axi_aclk 域，不跨时钟域。

新 HWH 的 Address Editor memory window 为 64 KiB，AXI 从端地址为 16 位。AXI 仿真已确认未定义的高偏移读写返回 SLVERR，且不会别名到低寄存器；新版位流已通过 667 帧实体板 UDP 回归，但无效偏移的物理 SLVERR 行为仍未直接探测。板上只访问寄存器表列出的偏移，不要通过 PYNQ MMIO 直接探测无效地址。

| 偏移 | 访问 | 用途 |
| --- | --- | --- |
| 0x000 | R | 设计 ID：0x46504732 |
| 0x004 | W | CONTROL bit0=1 启动一次检查，清除旧 done |
| 0x008 | R | STATUS bit0=busy，bit1=done_sticky |
| 0x010 | RW | 请求 profile_crc |
| 0x014 | RW | step |
| 0x018 | RW | flags |
| 0x01C | RW | feedback_age_us |
| 0x020 | RW | queue_depth |
| 0x040 | R | violations |
| 0x044 | R | events |
| 0x048 | R | scheduled_phase |
| 0x04C | RW | watchdog control，bit0=1 表示预期持续 `PERIODIC` 动作流 |
| 0x050 | W | watchdog ACTION_COMMIT 命令，bit0=1 产生单周期接受事件；只允许完整校验后的新动作写入，读回返回 SLVERR |
| 0x054 | R | watchdog 状态：bit0=PERIODIC，bit1=armed，bit2=expired |
| 0x058 / 0x05C | R | 自最近一次接受动作后的周期数，低/高 32 位 |
| 0x060 | R | watchdog 超时累计次数，饱和计数 |
| 0x064 / 0x068 | R | 最近一次接受动作间隔的周期数，低/高 32 位 |
| 0x100 + 4*i | RW | target[i]，i=0…13 |
| 0x140 + 4*i | RW | measured[i] |
| 0x180 + 4*i | RW | previous[i] |
| 0x1C0 + 4*i | RW | act[i] |
| 0x200 + 4*i | RW | correction[i] |
| 0x240 + 4*i | RW | previous_correction[i] |

默认 `WATCHDOG_TIMEOUT_CYCLES=25,000,000`；FCLK 为 50 MHz 时对应 500 ms，是交接方案提出的影子诊断初值，不是生产运动 deadline。只有 `PERIODIC` 模式并且首个有效动作 COMMIT 被 PS 完整校验后写入 `0x050` 时才武装；后续 ALLOW 和 HOLD 都应在各自通过校验后写入 COMMIT 以刷新计时。到期只锁存 `expired` 并将计数加一，不产生停止或放行动作。`ON_RESULT` 和暂停期间应清除 `0x04C` bit0；恢复后需先收到新的 COMMIT 才开始计时。

busy 时 wrapper 暂停接受写事务，防止一拍数据被覆盖；读事务继续可用。上层必须读 STATUS 确认空闲，依次写标量和六组向量，最后写 CONTROL；完成后只在 busy=0 且 done=1 时读取结果。单个 UIO 区域由单进程独占，不能让另一个进程交错写同一批向量。

UART/UDP header 中的 session、sequence、tick 和 elapsed_us 由 PS 保留并回显，当前 PL 不使用它们。board_processing_us 是 PS 从寄存器操作开始到读出结果的实测时间，包含 MMIO 和轮询，不等于 PL 纯计算延迟。

## 当前板端启动：PYNQ MMIO UDP 服务

将 `pynq_udp_runtime.zip` 上传到 Jupyter 工作目录并解压。运行包只含脚本；在解压目录下新建 `overlay/`（若不存在），并将最新 `.bit/.hwh` 放入其中。若要跑 PL 黄金向量回归，再将本机 `rtl/vectors.txt` 上传为 `board/vectors.txt`。

`board/pynq_udp_server.py` 语法检查和最新版本的 4 项 PYNQ MMIO/协议单元测试已通过。新版 16 位地址位流已通过 PYNQ 冒烟、1,678/1,678 组 PL 向量和 667/667 帧 UDP 自动参考比较；板端处理时间 min/median/mean/p95/max 为 2086/2134/2211.081/2366/10743 us，主机 UDP 往返为 3779.5/4699.5/4921.616/6882.4/16461.1 us。已知越界探针返回 `violations=00000001`；坏 CRC 报文无回包且板端记录 `DROP CRC mismatch`。服务锁定首个 host/session，新的有效请求前需重启服务。30 Hz 是主机循环的名义设置，并非有保证的 FPGA 请求间隔；下一项见 [PROGRESS.md](PROGRESS.md)。

查看板卡 IPv4（`!hostname -I`）和主机相连网卡 IPv4（Windows `ipconfig`）。将 `YOUR_PC_IP` 换成主机地址以限制 UDP 请求来源：

```text
python3 -u -m board.pynq_udp_server --bitfile overlay/own_hybrid_motion_guard_watchdog.bit --bind 0.0.0.0 --port 9009 --peer YOUR_PC_IP --log NEW_RUN_board.jsonl
```

在本机包目录已有 `replay_board_20261031` 回放文件。将 `YOUR_BOARD_IP` 换为板卡地址后，可带期望文件完成 667 帧整段自动比对：

```powershell
python -m host.link --udp YOUR_BOARD_IP:9009 --requests replay_board_20261031/requests.bin --limit 667 --timeout 3 --expected replay_board_20261031/expected.jsonl --summary-json replay_board_20261031/full_replay_summary_rtt.json
```

服务会逐帧比较 `violations/events/phase`，并分别保存板端报告处理时间和主机 send→matching-reply 往返时间的统计，以及结果掩码分布。全部匹配时打印 PASS。服务锁定首个来源和会话；每次启动新的 `host.link` 进程会创建新会话，因此再次回放前需重启板端服务。服务只回包检查结果，不接机器人控制链。若当前 Jupyter Terminal 中 Ctrl+C 无法停止服务，在另一个 Jupyter Terminal 查找并结束对应 PID：

```bash
ps -ef | grep '[b]oard.pynq_udp_server'
kill <实际PID>
```

结束后重新运行上面的板端启动命令。

## PS Linux UIO 备选方式

只有设备树将 guard 寄存器区域专门映射为 Device/uncached UIO 且实际 map 覆盖 `0x43c00000` 时，才使用下面的 UIO 实现。当前板卡的 `/dev/uio0` 映射不满足此条件。PS 使用 32 位对齐访问，现有实现通过 Python mmap 读写；它尚未在目标板上验证。没有 DMA 或缓存一致性协议。

将本包放到 PS Linux 上，完成位流与 UIO 配置后：

```bash
# 仅当设备树中的专用 UIO map 覆盖 guard 基址时使用；当前板卡的 uio0 不满足。
python3 -B -m board.ps_uio_server --uio <guard_uio_device> --port 9009
```

本机先用 host.replay 生成 requests.bin，再执行：

```bash
# 在本机运行，替换 ZYNQ_IP 为板卡实际地址。
python3 -B -m host.link --udp ZYNQ_IP:9009 --requests output/replay_134006/requests.bin --limit 10
```

两种桥接都固定单一来源地址和会话，丢弃旧序号/旧时间戳；PYNQ 服务可用 `--peer` 限制源 IP，切换会话需显式重启进程。PL 超时会停止服务，不返回伪造的通过结果。桥接代码不写 CAN、不控制使能或急停，也没有控制现有机械臂。

## UART 备选

如果板卡只有 USB 转 PS UART，可以复用同一帧协议，将串口接收、FrameStream 和 serve_packet 连接起来；AXI 与 PL 无需更改。目前提供的是主机 UART 工具和 PS UDP bridge，**没有已完成的 PS UART 服务端**。PS Linux 控制台占用的串口不能同时作为本协议链路，应在板卡实际系统中选择空闲端口。若使用裸机 Vitis，则需用板卡 BSP 的 UART/网络接口和寄存器访问替换 Python UIO 层；本包没有声称已适配某个 BSP。
