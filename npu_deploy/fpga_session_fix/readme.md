# FPGA 诊断会话重复运行修复草稿

这两份文件是板端源码的候选修改，尚未部署到 PYNQ，也没有做过板上测试。
原有 FUI1、FPG1 只接受一个发送端和会话，发送端退出后不会释放；本修改在
旧会话最近一次有效请求后空闲 5 秒时，允许新的会话从序号 0 接入，并减少
FPG1 的终端打印量。其余请求顺序和包校验不变。超时后原发送端若仍在运行，
可能被新的会话替换，适用于单个主机的诊断旁路，不能作为动作门控或安全机制。

这不能修复或解释整板死机、电源或网络断链。必须先检查 FPGA 本机响应、
现场配置和板上源码版本，再安排一次板端重启服务和连续两次的实际回归测试。
如板上源码与原始 `fpga_integration/board_runtime/board` 版本不同，不得直接覆盖。

在 AI PC 执行离线协议测试：

```bash
python3 npu_deploy/fpga_session_fix/test_session.py
```
